From src/ui/income-sources.js — _handleAddSource() (lines 168–176):
```js
async _handleAddSource(data) {
  try {
    await incomeSourceRepository.validateAndAdd(data);
    triggerHaptic('success');
    await this.render();
  } catch (err) {
    notificationUI.error(err.message);
  }
},
```
The duplicate bug is likely caused by event listeners accumulating on the container. The `_bindEvents`
method attaches `container.addEventListener('click', async e => {...})` every time `render()` is called.
Each re-render calls `_bindEvents(container)` again — without removing the previous listener — causing
the click handler to fire multiple times per click after the first render.

Fix: use `{ once: true }` on the listener OR replace the container's innerHTML before re-attaching
(which clears old listeners on child elements but NOT on the container itself since it persists across
renders). The correct fix is to track whether the listener is already bound:

Option A — use `container.replaceWith(container.cloneNode(false))` to get a fresh container node before
each render (clears all listeners). This is the simplest fix but requires updating the container
reference in render().

Option B — assign the handler as a property and use removeEventListener before adding:
```js
if (this._boundClickHandler) {
  container.removeEventListener('click', this._boundClickHandler);
}
this._boundClickHandler = async e => { ... };
container.addEventListener('click', this._boundClickHandler);
```

Use Option B — it is surgical, doesn't require DOM manipulation, and follows the existing
`_authListenerBound` guard pattern used elsewhere in this project.
