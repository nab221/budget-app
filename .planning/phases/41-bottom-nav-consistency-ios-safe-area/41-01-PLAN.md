Two changes to index.html:

1. On line 5, add `viewport-fit=cover` to the meta viewport tag:
   BEFORE: `<meta name="viewport" content="width=device-width, initial-scale=1.0" />`
   AFTER:  `<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover" />`

```html
<body>

```

CRITICAL: Move the nav block exactly as-is — do not change any attributes, IDs, classes, or child elements inside the nav. The nav's `position: fixed; bottom: 0; left: 0; right: 0` CSS means its visual position is viewport-relative regardless of DOM location. The JavaScript tab switching uses `document.getElementById('mainTabs')` — ID-based lookup, unaffected by DOM position.

Do NOT add transform, will-change, filter, or contain to .shell at any point.

<task type="auto">
  <name>Task 2: Update .shell mobile padding-bottom to include env(safe-area-inset-bottom, 0px)</name>
  <files>css/main.css</files>
  <action>
In css/main.css, inside the `@media (max-width: 768px)` block, update the `.shell` padding-bottom rule.

FIND (line ~241):
```css
.shell { padding-bottom: calc(var(--bottom-bar-height) + 8px); }
```

REPLACE WITH:
```css
.shell { padding-bottom: calc(var(--bottom-bar-height) + env(safe-area-inset-bottom, 0px) + 8px); }
```

Why: Once viewport-fit=cover is active (Task 1), env(safe-area-inset-bottom) returns ~34px on iPhones with a home indicator. The .nav-container padding-bottom already uses this value (the existing rule is correct and activates automatically). The .shell padding-bottom must mirror the nav height — if the nav grows taller by the safe-area amount, the shell must add the same amount to keep the last content item above the nav bar (BOTNAV-02).

The `, 0px` fallback in env(safe-area-inset-bottom, 0px) is required for correct behavior inside calc() on non-iOS devices.

Do NOT change any other .shell rules, the desktop .shell rule, or any other CSS in the file.
  </action>
