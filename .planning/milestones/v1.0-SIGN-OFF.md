### Cloud Backup

**Status: CONFIGURATION REQUIRED — not a code defect**

| Check | Result | Notes |
|-------|--------|-------|
| Google Drive OAuth popup | CONFIG | Console: "Google Drive init deferred: Missing required parameter client_id" |
| OneDrive OAuth popup | CONFIG | Console: "BrowserAuthError: timed_out" — auth popup opened but OAuth flow incomplete |
| Persistence across reload | NOT TESTED | Cannot verify without successful OAuth connection |
| Offline guards on buttons | NOT TESTED | Cannot fully verify without active connection |

**Root cause:** Neither Google Drive nor OneDrive OAuth credentials are configured in the development environment. The application code loads correctly, deferring initialisation when `client_id` is absent. This is expected and correct behaviour.

**Classification:** This is a **user setup requirement**, not a code defect. Each deployment must supply:

- **Google Drive:** A Google Cloud project with an OAuth 2.0 client ID registered for the app's origin, set as `VITE_GOOGLE_CLIENT_ID` (or equivalent config injection).
- **OneDrive:** An Azure App Registration with the correct redirect URI, set as `VITE_ONEDRIVE_CLIENT_ID` (or equivalent).

**Action for users:** Refer to the cloud backup setup documentation to supply OAuth credentials before enabling cloud sync. Cloud backup features are gated behind successful OAuth configuration and will remain silently disabled until credentials are provided.
