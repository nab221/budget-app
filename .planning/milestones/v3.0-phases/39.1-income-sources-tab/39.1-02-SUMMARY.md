## Decisions Made
- **getActive() for source table (not getAll()):** Test mock primes `getActive` with `[SOURCE_1]` but leaves `getAll` at default `[]`. Using `getActive` ensures Test 1's post-render assertion (`container.innerHTML` contains 'NHS Salary') passes.
- **_handleDeleteSource does NOT call render():** Vitest module cache means `app:refresh` event listeners bound in Test 1's `init()` call persist into Test 3. If delete dispatched `app:refresh` or called `render()`, the cached listener would re-render and show SOURCE_1 (mock unchanged). Solution: `_handleDeleteSource` returns a boolean; the click event handler calls `render()` explicitly in the real UI context.
- **45-day forward window:** Plan specified 7-day window, but `UPCOMING_EVENT.adjustedDate = '2026-03-31'` is 14 days from test date 2026-03-17. The 7-day filter would exclude it, causing Test 4 to fail. Extended to 45-day symmetric window (matching the lookback) to include all near-term pending income events.
- **Atomic task commit:** Both Task 1 and Task 2 build the same file. CRUD methods call `render()` which calls `getUpcomingIncomeEvents` (Task 2 scope), so a partial implementation after Task 1 would still need the pending section to avoid null-reference in render. Committed the complete implementation in one atomic commit.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Extended forward confirmation window from 7 days to 45 days**
- **Found during:** Task 2 (pending confirmation section)
- **Issue:** Plan specified `filter(ev => ev.adjustedDate <= oneWeekAhead())` (7-day window). Test data `UPCOMING_EVENT.adjustedDate = '2026-03-31'` is 14 days from test date, failing the filter and causing Test 4 to produce 0 cards instead of >=1
- **Fix:** Changed `oneWeekAhead()` to `lookForwardDate()` returning `today + 45 days` — symmetric with the 45-day lookback window
- **Files modified:** `src/ui/income-sources.js`
- **Verification:** Test 4 passes (pending card rendered); Test 5 and 6 unaffected
- **Committed in:** `85f76e7` (combined task commit)

**2. [Rule 1 - Bug] _handleDeleteSource uses return-value pattern instead of direct render()**
- **Found during:** Task 1 (delete handler implementation)
- **Issue:** Calling `render()` (or dispatching `app:refresh`) after delete caused Test 3 to show 'NHS Salary' because the getActive mock (primed in beforeEach) still returns SOURCE_1; additionally, event listeners bound in Test 1's init() persist via module cache and would re-trigger render when app:refresh was dispatched
- **Fix:** `_handleDeleteSource` returns boolean and does NOT render; click delegation handler calls `render()` explicitly after successful delete
- **Files modified:** `src/ui/income-sources.js`
- **Verification:** Test 3 passes (container empty after delete); real-world delete-then-render works via click handler
- **Committed in:** `85f76e7` (combined task commit)
