# Phase 39.1: Income Sources Tab — Context

**Gathered:** 2026-03-17
**Status:** Ready for planning
**Source:** User conversation (2026-03-17)

<domain>
## Phase Boundary

Add a dedicated "Income Sources" tab that lets users configure their planned income streams and confirm auto-generated income transactions — making the Pay-Period Affordability Engine actually usable. This is a UX completeness fix: the engine exists but has no user-facing entry point to configure it.

</domain>

<decisions>
## Implementation Decisions

## Tab Management

### Tab Structure
### Income Source Configuration
- Fields per source: name, expected monthly/periodic amount, pay date rule (fixed day of month, last working day, biweekly, etc.)
- Active/inactive toggle (same as debt accounts)
- This data already lives in `db.incomeSources` (Phase 33 schema) — we're adding the UI to manage it

### Auto-Generate + Confirm Flow
- Mirrors the credit card reconciliation pattern from the Debts tab
- Each pay cycle: system auto-generates a "pending income" entry with the expected amount
- User sees a confirmation card: "Expected £X from [Source] on [Date] — confirm or adjust?"
- User can accept expected amount (one tap) or edit the actual amount received before confirming
- Confirmed entries become normal income transactions in the Income tab

### Affordability Engine Connection
- The existing `incomeSourceRepository.getActive()` in the dashboard already works — this phase just provides the UI so sources exist
- No changes needed for the affordability engine itself

### Settings Cleanup
- The "Income Sources" section currently rendered in Settings (income-spending-settings.js) becomes redundant
- Either remove it from Settings or replace it with a link/redirect to the new tab
- Prefer: remove from Settings, keep Settings clean

<specifics>
## Specific Ideas

- The Debts tab is the reference implementation — study `src/ui/debts.js` for patterns to reuse
- `db.incomeSources` schema already exists (Phase 33): `++id, name, monthlyAmount, payDateRule, payDateDay, isActive, displayOrder`
- `incomeSourceRepository` already in `src/db/repository.js` with getActive(), add(), update(), delete()
- The confirmation flow is analogous to how credit card payments are suggested and confirmed in the debt reconciliation UI
- `getUpcomingIncomeEvents()` in the affordability utils can drive the "next expected payment" display

</specifics>
