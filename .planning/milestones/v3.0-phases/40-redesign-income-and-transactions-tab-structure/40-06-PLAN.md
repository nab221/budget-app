From src/app.js — expenses renderAll() branch (line ~135):
```js
if (panelId === 'expenses') renderTasks.push(expensesUI.render());
```
After removing the Expenses tab, panelId will never equal 'expenses' from a tab click. However,
expensesUI still needs to render its internal state when the Transactions tab is active (so that
edit modals show current data). The simplest approach:
- Remove the standalone `if (panelId === 'expenses')` branch
- Add `expensesUI.render()` to the `if (panelId === 'transactions')` block so both render together:
  ```js
  if (panelId === 'transactions') {
    renderTasks.push(transactionUI.render());
    renderTasks.push(expensesUI.render());   // expenses state kept current for modals
  }
  ```
  NOTE: expensesUI.render() will fail silently if #expBody is not in the DOM (expenses panel removed).
  Verify that expensesUI.render() has a DOM-presence guard (it checks for `const body = document.getElementById('expBody'); if (!body) return;`). If it does, no further change needed.

From index.html — Expenses panel block to remove (lines ~172–240):
The entire `<div class="tab-panel" data-panel="expenses">` block including:
- expMonthPicker
- expensesTabHeatmapSection / expensesTabHeatmapContainer
- expensesSummary
- expReconHeader
- Add Expense button row (markAllPaidBtn, triggerRecurrenceBtn, expSearch, expCategoryFilterContainer)
- The unified expense table (expHead, expBody)

All of these DOM elements are currently referenced from expenses.js. After removing the panel, any
expenses.js render calls will encounter missing elements and return early (guarded by getElementById
checks). This is safe — expenses.js event listeners bound in setupEventListeners() are set up on
ids that won't exist, so onclick assignments to null do nothing.

IMPORTANT: The `#addExpenseBtn` is currently in the Expenses panel. Moving it to the Transactions
panel means expenses.js setupEventListeners() will find it in the new location — no change needed
to expenses.js because it just does `document.getElementById('addExpenseBtn')`.

Similarly, `#triggerRecurrenceBtn` and `#markAllPaidBtn` should also move to the Transactions panel
toolbar (or be removed if not needed in the merged view). Move them to keep full expense management
accessible. The search input `#expSearch` and `#expCategoryFilterContainer` are specific to expenses.js
filtering — move them into the Transactions panel toolbar as a secondary filter row (hidden by default,
or combined with the existing income filter row).

Simpler approach for the filter controls: move `#expSearch`, `#expCategoryFilterContainer`,
`#markAllPaidRow`, and `#triggerRecurrenceBtn` into the Transactions panel toolbar as a second row
below the existing income controls. Label them visually as "Expense Filters:" to distinguish.
