# Phase 1: Header & Banner Cleanup

## Objective
Ensure UI state reflects true persistence status and clarify data management actions.

## Context
The application current has some confusing UI around data persistence and resetting. With the introduction of file-sync, the "Persistence Warning" banner might be misleading if the user is auto-saving to a file. Also, the database reset button is too generic and doesn't explain that it wipes IndexedDB.

## Tasks
1. **Update index.html** to rename the legacy reset button. `type="auto"`
2. **Update src/ui/backup.js** to handle the renamed reset button with new confirmation logic and warning for active file-sync. `type="auto"`
3. **Update src/ui/file-sync.js** to rename and restyle the disconnect button, and update the header hint text dynamically. `type="auto"`
4. **Update src/app.js** to modify the persistence banner visibility logic. `type="auto"`
5. **Ensure persistence banner state is refreshed** when file-sync status changes. `type="auto"`

## Verification/Success Criteria
1. Persistence banner only appears when `ensurePersistence()` is false AND no file-sync handle is active.
2. DB reset button is renamed to "🗑 Clear All Data" and shows a confirmation dialog.
3. Disconnect button is renamed to "🔗 Disconnect File" with secondary styling and confirmation.
4. Header hint text dynamically updates based on file-sync status.
