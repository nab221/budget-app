# Phase 05.1 Context: PDF Import Stabilization

## 1. Verification Protocol
- **Automated Verification:**
    - Mandatory unit tests for `src/utils/pdf-parser.js` using anonymized text samples for all supported bank formats (NatWest, Barclays, Lloyds, etc.).
    - Automated schema validation for all parsed transactions (ensure `pence` integers, correct date formats, and required fields).
- **Manual Verification:**
    - Create `05-UAT.md` logging successful imports for each bank format with diverse transaction types (interest, transfers, spending).
    - Manual verification of PWA-specific behavior (PDF upload while installed on desktop/mobile).
- **Success Criteria:** All PDF requirements (PDF-01 to PDF-05) must be marked satisfied in `05-VERIFICATION.md` following these protocols.

## 2. Post-Import UX (Refresh & Feedback)
- **Informative Feedback:**
    - Display a summary toast on successful import: "Imported [X] transactions. Skipped [Y] duplicates."
    - Display a "Review Conflicts" badge if duplicates are detected.
- **Navigation & Workflow:**
    - The app must stay on the Import page after a successful import to allow for subsequent statement uploads.
    - Implement a global `refreshApp()` or custom event signal that all UI modules (Dashboard, Charts, Lists) listen for, ensuring immediate visual updates without a full reload.

## 3. Error Resilience & Feedback
- **Partial Import Handling:**
    - If the parser extracts some rows correctly but fails on others, show the "clean" rows for preview and provide a clear warning for the failed rows with a recommendation for manual entry.
- **Diagnostic Support:**
    - Implement a "Copy Debug Info" button on parsing error screens that exports a scrubbed version of the PDF's text structure for troubleshooting.
- **Error Boundaries:**
    - Wrap the `PDFImport` UI component in a React/Vanilla JS error boundary to prevent ReferenceErrors from crashing the entire app shell.

## 4. Stabilization & Refactoring Scope
- **Core Fixes:** Resolve ReferenceErrors in `pdf-import.js` (e.g., `fixedSpendRepository`, `toPence`).
- **Tech Debt & Modularity:** 
    - Allowed to remove dead code and refactor `pdf-import.js` for better modularity (separating parser logic from UI state).
    - Ensure `pdf-parser.js` and `pdf-import.js` use consistent import patterns from `repository.js` and `currency.js`.
- **UI Polish:** 
    - Minor alignment, spacing, and icon consistency fixes are allowed to ensure the Preview UI matches the app's overall aesthetic.
