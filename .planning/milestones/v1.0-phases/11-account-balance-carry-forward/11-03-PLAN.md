<task type="checkpoint:decision" gate="blocking">
  <name>Task 1: Decide Balance Start Date Input Type</name>
  <decision>Should `input#balanceStartDate` remain `type="month"` (YYYY-MM picker, consistent with how snapshots are keyed) or switch to `type="date"` (full day picker, with day truncated to "01" on save)?</decision>
  <context>
    The balance snapshot schema keys by YYYY-MM string. The Settings save handler already reads the value and stores it as-is in localStorage. If `type="month"`, the browser renders a month-year picker (e.g. "March 2026") — no day selection. If `type="date"`, the browser renders a full date picker and the save handler must truncate the value to YYYY-MM before storing. The label currently reads "Start Month" which aligns with the month-only picker.
  </context>
  <options>
    <option id="keep-month">
      <name>Keep type="month"</name>
      <pros>Zero code change needed. Consistent with YYYY-MM schema. Label "Start Month" already matches.</pros>
      <cons>Some users may not recognise the month-year browser widget or expect to set a specific day.</cons>
    </option>
    <option id="switch-date">
      <name>Switch to type="date", truncate on save</name>
      <pros>Standard date picker UX users recognise. More intuitive to pick a start day.</pros>
      <cons>Requires updating index.html and the save handler to slice value to YYYY-MM. Day part is discarded silently.</cons>
    </option>
  </options>
  <resume-signal>Select: keep-month OR switch-date</resume-signal>
</task>

    ```javascript

      db.recurrentExpenses.where('nextDate').startsWith(monthStr).toArray();
    ```
