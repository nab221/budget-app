# Phase 30-01 PLAN: Edit/Delete Lifecycle

## Goal
Implement the user choice logic for editing and deleting recurring transaction instances.

## Requirements Traceability
- [x] **RECURRENCE-UI-04**: Implement `recurrenceModal` for "This vs All Future" choice.
- [x] **RECURRENCE-OPS-01**: Update `delete` handlers to handle series removal.
- [x] **RECURRENCE-OPS-02**: Update `update` handlers to handle series modification.

## Implementation Steps

### 1. Update Repositories (`src/db/repository.js`)
- Add `deleteSeries(recurrenceId, fromDate)` to `recurrentExpenseRepository` and `oneOffExpenseRepository`.
- Add `updateSeries(recurrenceId, fromDate, updates)` to both repositories.
- Ensure triggers (`triggerBalanceRecalc`, `triggerDailyForecastRecalc`) are called.

### 2. Implement `recurrenceModal` in `src/ui/expenses.js`
- Create a helper `promptRecurrenceChoice(title, message)` that returns a Promise resolving to `'this'` or `'future'` or `null`.
- Use `templateUI.showModal()` to render the choices.

### 3. Update Delete Handlers in `src/ui/expenses.js`
- Refactor `window.deleteRecurrentExpense` and `window.deleteOneOffExpense`.
- If `item.recurrenceId` exists, call `promptRecurrenceChoice`.
- Route to `repository.delete(id)` or `repository.deleteSeries(recurrenceId, date)`.

### 4. Update Save Handler in `src/ui/expenses.js`
- In `handleSaveExpense`, if `this.editingId` and `item.recurrenceId`:
    - Call `promptRecurrenceChoice`.
    - If `'future'`, call `repository.updateSeries`.
    - Note: If `frequency` changed, the logic might need to wipe and regenerate. For now, I'll focus on field updates (label, amount).
