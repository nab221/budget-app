<task type="auto" tdd="true">
  <name>Task 1: Core Recurrence Logic (generateInstances)</name>
  <files>src/utils/recurrence.js, src/utils/recurrence.test.js</files>
  <behavior>
    - frequency='weekly': returns array with dates incremented by i+1 weeks from base date.
    - frequency='biweekly': returns array with dates incremented by (i+1)*2 weeks from base date.
    - frequency='monthly': returns array with dates incremented by i+1 months (using date-fns addMonths).
    - frequency='quarterly': returns array with dates incremented by (i+1)*3 months.
    - frequency='annually': returns array with dates incremented by i+1 years.
    - Each instance must have isRecurring: true and the same recurrenceId.
    - IDs (primary keys) from the base object should be removed in generated instances.
    - Fields date, nextDate, and predictedPaymentDate (if present) should all be updated to the new date.
  </behavior>
  <action>
    Implement `generateInstances(base, frequency, count)` in `src/utils/recurrence.js`.
    Use `date-fns` for all date math.
    To avoid month-end drift (e.g. Jan 31 -> Feb 28 -> Mar 28), always calculate instances by adding the interval to the *original* base date (parentDate) using `i + 1` steps.
    If base has no `recurrenceId`, generate one using `crypto.randomUUID()`.
    Ensure the returned array has exactly `count` items.
  </action>
  <verify>
    <automated>npm test src/utils/recurrence.test.js</automated>
  </verify>
  <done>Pure function generateInstances passes all TDD cases for all supported frequencies and preserves data integrity.</done>
</task>
