- `importBackupData` shared utility — both `backup.js` and `cloud-backup.js` use the same path
- `CLOUD_LAST_BACKUP_KEY` consolidated in `storage.js` — imported by all 3 cloud modules
- Dexie schema v1→v9 chain — no missing versions; v3 skip documented
- `childcareRepository.addDeposit` → `oneOffExpenses.add()` side-effect → `expenses.js` TFC badge
- `getDashboardData` returns `childcareSummary`, `bucketSpending`, promo alert data — all consumed
- `renderBalancePanel` + `renderBalanceChart` unconditionally called in `renderDashboard`
- `calculateBalanceChain` triggered on startup (app.js:144–148) and by income/oneOff mutations

### Integration Defects

#### DEFECT 1 — Functional Gap (BAL-02)
**`recurrentExpenseRepository` mutations do not trigger balance recalculation**

- **File:** `src/db/repository.js` lines 362–393
- **Root cause:** `incomeRepository` and `oneOffExpenseRepository` override `add/update/delete` to call `triggerBalanceRecalc(date).catch(() => {})`. `recurrentExpenseRepository` uses the base repository without overrides.
- **Impact:** Adding, editing, or deleting a recurrent expense does not recalculate balance snapshots and does not dispatch `app:refresh`. The balance panel displays stale projections until the next income or one-off expense mutation.
- **Fix:** Mirror `incomeRepository` override pattern (lines 276–299) in `recurrentExpenseRepository`.

#### DEFECT 2 — Accuracy Gap (BAL-01, BAL-03)
**`calculateBalanceChain` ignores `nextDate` when summing projected recurrent expenses**

- **File:** `src/utils/finance.js` lines 267–268
- **Code:** `getRecurrent = async (_monthStr) => db.recurrentExpenses.toArray()`
- **Root cause:** Plan 11-03 fixed a broken `.startsWith()` filter (that returned empty results for future months) by removing the filter entirely. This overcorrects — it now counts ALL recurrents in every projected month.
- **Impact:** A quarterly expense (e.g. £600/quarter) is counted 3× in a 3-month projection instead of 1×. Balance projections overstate future expenses proportional to the number of non-monthly recurrents.
- **Contrast:** `getDashboardData` (repository.js:571) correctly filters `.where('nextDate').startsWith(targetMonth)`.
- **Fix:** Apply frequency-aware filtering — include a recurrent item in a projected month only if its `nextDate` (or next cycle date) falls in that month.

#### DEFECT 3 — Informational (SUB-01–04)
**`subscriptionUI` is orphaned dead code**

- **File:** `src/ui/subscriptions.js`
- `subscriptionUI.init()` is never called from `src/app.js`
- `subscriptionRepository` is a no-op stub (repository.js:441–443); `subscriptions` table removed in schema v5
- **Impact:** None — SUB-01–04 are satisfied by Phase 8 `recurrentExpenses` implementation
- **Fix:** Delete `src/ui/subscriptions.js` and remove stub from `repository.js`
