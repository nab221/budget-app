# Milestone v1.5 Requirements: Automatic Recurring Transactions

## Goal
Replace the manual "Templates" system with a true automatic recurrence engine. Introduce month-based navigation for all expense views to handle future-dated transactions gracefully.

## 1. Database Schema Changes (Version 12)

### Table: `recurrentExpenses` (Fixed Spends)
- `isRecurring`: boolean (default: true)
- `frequency`: string enum ('weekly', 'biweekly', 'monthly', 'quarterly', 'annually')
- `recurrenceId`: string (UUID shared by all instances in a series)
- `parentDate`: ISO date string (original start date of the series)

### Table: `oneOffExpenses` (Variable Spends)
- `isRecurring`: boolean (default: false)
- `frequency`: string enum (same as above)
- `recurrenceId`: string (UUID)
- `parentDate`: ISO date string

### Table: `recurringTemplates`
- **Action**: Drop table after migration.

## 2. Recurrence Logic

### Generation
- When a recurring transaction is created:
    1. Generate a `recurrenceId` (UUID).
    2. Create the first instance.
    3. Generate the next 12 months (or equivalent for other frequencies) of instances.
    4. Store all as individual records in their respective tables.
- **Auto-Generation Trigger**: On app load, if the latest instance for a `recurrenceId` is within 2 months of the current date, generate the next batch.

### Frequency Mapping
- `weekly`: +7 days
- `biweekly`: +14 days
- `monthly`: +1 month (Smart handling for month-ends via `addMonths`)
- `quarterly`: +3 months
- `annually`: +12 months

## 3. UI Changes

### Month Navigation
- Add a persistent Month Picker to both **Recurrent** and **One-off** expense sub-tabs.
- Format: `[◄ Prev] [Month Year Dropdown] [Next ►]`
- Filter table rows strictly by the selected month.
- Default to the current month on load.

### Transaction Forms
- Add "Recurring" checkbox.
- Add "Frequency" dropdown (disabled unless Recurring is checked).
- Update submission handlers to trigger batch generation if Recurring is checked.

### Edit/Delete Behavior
- If a transaction has a `recurrenceId`:
    - **Edit**: Prompt "Edit this occurrence" or "Edit all future".
    - **Delete**: Prompt "Delete this occurrence" or "Delete all future".
- "All future" updates/deletes all records with the same `recurrenceId` where `date >= selected_date`.

## 4. Migration from Templates
- Upgrade logic (Schema v12):
    1. Iterate through `recurringTemplates`.
    2. Convert to recurring transactions starting from the current month.
    3. Generate 12 months of instances.
    4. Delete the `recurringTemplates` table.
- Remove "Templates" section from Settings UI.

- [x] Adding a recurring "Rent" generates 12 future instances. [PASSED]
- [x] Navigating to a future month shows the pending instances. [PASSED]
- [x] Deleting "all future" instances correctly clears the series from that date forward. [PASSED]
- [x] Existing templates are converted to the new system on first run. [PASSED]
